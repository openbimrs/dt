Pure-Rust contracts for ISO 23387 data templates: the vocabulary used to
describe properties, groups of properties, object types, quantity kinds,
dimensions, units, and their references.

This repository is the canonical home of the data-template family in
[OpenBIM.rs](https://github.com/openbimrs/openbim). Its integration location is
`packages/dt`, where the superproject records an exact child revision.

## Status

Version `0.1.1` is a **reserved namespace scaffold**, not an ISO 23387 model,
parser, writer, or validator.

| Capability | Status |
| --- | --- |
| ISO 23387 edition 2 namespace identity | Implemented and unit-tested |
| Known draft placeholder namespace identity | Implemented and unit-tested |
| ISO 23387 domain model | Not implemented |
| XML parsing or writing | Not implemented |
| XML Schema validation | Not implemented |
| Semantic validation and diagnostics | Not implemented |
| ISO 23386 governance workflow | Not implemented |
| ISO 12006-3 mapping | Not implemented |
| LOIN or bSDD integration | Not implemented |

No model, codec, conformance, validation, or lossless-round-trip capability
should be inferred from the crate existing on crates.io.

## Why DT is separate from LOIN

ISO 7817-3 LOIN imports the ISO 23387 vocabulary, but LOIN does not own it.
Data-template authoring, dictionary tooling, and other consumers need the same
lower-level contracts without depending on LOIN.

```text
openbim-core  <-  openbim-dt  <-  openbim-loin / dictionary clients
```

The `openbim` facade may make its `loin` feature imply `dt`; the dependency must
never point from data templates back to LOIN.

## Install

```bash
cargo add openbim-dt
```

```rust
use openbim_dt::{DRAFT_PLACEHOLDER_NAMESPACE, NAMESPACE};

assert_eq!(NAMESPACE, "https://standards.iso.org/iso/23387/ed-2/en/");
assert_ne!(NAMESPACE, DRAFT_PLACEHOLDER_NAMESPACE);
```

## Standards and fixtures

No ISO, DIN, or CEN document, XSD, or annex example is distributed by this
repository, its crate, or its documentation site. Legally accessed references
belong under the ignored local `references/` directory.

The available ISO 23387 Annex F example is standards material and is therefore
not copied to `tests/fixtures/`. Fixtures may be committed only when they are
original synthetic documents or have explicit redistribution terms compatible
with this repository.
